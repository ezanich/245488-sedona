## Решения — сверять по пунктам

### Структура справочника

**1.** Справочник работ **плоский**. Иерархию по типам изделий как основную структуру не делать: «Замена троса», «Выезд», «Монтаж лампы сигнальной», «Программирование таблетки» встречаются в 3–5 ветках. Дерево заставит либо дублировать позицию в каждой ветке, либо потерять срез.

**2.** Четыре оси из таблицы выше заводятся как **доп. реквизиты** типа «перечисление» (в УТ/ERP — доп. реквизиты вида номенклатуры, в УНФ — доп. реквизиты справочника). Не строками, не папками.

**3.** Иерархия папок — **одна, плоская, по типу изделия**, исключительно для навигации глазами. Все остальные срезы — отборами по реквизитам.

**4.** Правило именования, зафиксировать письменно **до** загрузки:
```
<Действие> <узел/объект> <тип изделия>, <уточнение/класс>

✔ Замена троса секционных ворот, до 6 м²
✔ Замена троса секционных ворот, 6–10 м²
✔ Регулировка торсионного механизма, бытовые до 9 м²
✘ Троса замена
✘ Демонтаж/монтаж троса + троса     ← две работы и материал в одной строке
```
Единый порядок слов — это и есть механизм, который чинит 28 коллизий: `Столб 80×80×3, h до 3 м, с бетонированием (ворота)` и `(забор)` становятся разными позициями, и разные цены становятся законными.

**5.** Базовая единица измерения выбирается **один раз и не меняется** — после проведённых документов её смена невозможна без заведения новой позиции. Одна работа = одна единица. Если работа продаётся и «за шт», и «за м²» — это **две номенклатуры**.

**6.** Вид номенклатуры (набор реквизитов + счета учёта + ставка НДС) определяется **до** загрузки. Минимум: «Работы монтажно-ремонтные», «Материалы», «Товары поставщиков», «Транспорт/логистика». Смена вида у позиции с движениями — болезненная операция.

### Ценообразование

**7.** Три типа цен разделяются физически и не смешиваются в поле «Цена».

**8.** Тип **C (проценты и коэффициенты) номенклатурой не заводится**. Три разных механизма:

| Что | Механизм 1С |
|---|---|
| Безнал +12% | отдельный **вид цен**, рассчитываемый от «Розница нал» с наценкой (штатная формула в карточке вида цен) |
| Ночные ×2 · Выходные ×2 · Срочный выезд ×2 · Этажность +50% · Высотные +30% | **автоматические скидки/наценки** с условием, на документ или группу строк |
| Демонтаж = 50% от монтажа | **посчитать и зафиксировать числом**. Это не формула. Три разных написания одного правила в прайсе — уже источник разночтений |

Причина: наценка, оформленная как наценка, попадает в отчёт о структуре выручки. Наценка, вбитая руками отдельной строкой, не попадает никуда.

**9.** Пороговые тарифы («до 10 м²» фикс / «свыше 10 м² = 1600 руб/м²») разносятся на **две позиции** с разными единицами, а не одна с плавающей единицей. Таких пар в прайсе много.

**10.** 194 позиции типа D и E разводятся вручную на один из трёх исходов:
   1. конкретное число (большинство «от 6000» на практике = 6000);
   2. разбивка на 2–3 класса по габариту — приём уже применён для пружин («до 9 / 9–16 / свыше 16 м²»), распространить;
   3. позиция с ценой 0 и признаком **«Цена по расчёту»** — менеджер обязан вписать цену руками, но она привязана к позиции и копится статистика. Через полгода медиана превращается в прайс.

Это ручная работа, которую нельзя делегировать — только пользователь знает, 500 или 1300 стоит обшивка в каждом контексте.

**11.** Коэффициент безнала привести к **одному** значению. Сейчас в расчётах 1,11 / 1,12 / 1,15. Отдельно проверить, не устарел ли он: 12% похоже на УСН, а с 2025 при обороте свыше порога появляется НДС 5/7% — арифметика меняется.

**12.** **Порядок применения наценок** (подтверждён на данных, сходится до рубля):
```
закупка → +интерес (%) → +доставка → +монтаж → ×безнал → −скидка
```
Безнал — предпоследним, скидка — последней.

### Нормо-часы

**13.** Нормо-часы вводятся как реквизит `Норма времени, ч`, **заполняется по факту**, не подгоняется под цену. Цена пока остаётся фиксированной, как в прайсе.

Почему нельзя сразу на формулу `цена = норма × ставка`: прайс не линеен по времени. `Замена тросов: до 6 м² = 6000 · 6–10 м² = 7000 · свыше 10 м² = 8500` — это не пропорция трудозатрат, в ступенях зашиты риск, вес и высотка. Деление цены на часы даст разную ставку нормочаса на разных работах и обессмыслит модель.

**14.** Нужен второй реквизит — `Коэффициент сложности` (1,0 / 1,3 / 1,8: высотка, стеснённые условия, промышленные габариты).

**15.** Через 2–3 месяца построить отчёт `Цена ÷ (Норма × Коэффициент)` → получить фактическую ставку нормочаса по каждой работе → увидеть, где работа идёт себе в убыток. **Только после этого** переходить на формулу.

**16.** В прайсе уже три разные часовые ставки, их надо свести к одной модели:
```
Ремонтные работы (чел.час)      2 000
Нетиповые расходы, бригада/час  3 000
Арматурные работы (за час)      3 600
```

Пользовательская формулировка задачи (из первой строки прайс-файла): *«Нужно привязать цены к нормочасам — тогда можно будет менять только стоимость нормочаса и всё остальное будет меняться само»*. Цель правильная, путь — через пп. 13–16, а не напрямую.

### Товары поставщиков

**17.** Товар поставщика **всегда заводится как Товар**, никогда как услуга. Заведение ворот «услугой», чтобы они спрятались в акте, ломает: приход по накладной поставщика, себестоимость и маржу, складские остатки, расход для налоговой, привязку серийников и гарантии.

**18.** Счёт учёта — **10 (материалы)** при схеме «подряд из материалов подрядчика», либо 41 при перепродаже. Согласовать с бухгалтером **до** заведения: счёт прописывается в виде номенклатуры, менять задним числом по проведённым документам больно.

**19.** **«Под ключ одной строкой» достигается не типом номенклатуры, а разделением двух слоёв:**
```
УЧЁТНЫЙ СЛОЙ (внутри 1С)
├── Ворота Zaiger ECO 3000×3000, антрацит   [Товар, сч. 10.01]  109 000
├── Привод Nice SN6041                      [Товар, сч. 10.01]   32 000
├── Комплект крепежа                        [Товар]               2 000
├── Доставка                                [Услуга]             25 000
└── Монтаж секционных ворот до 10 м²        [Работа]             20 000
                      ↓ спецификация / набор
ПЕЧАТНЫЙ СЛОЙ (акт для клиента)
└── «Поставка и монтаж секционных ворот 3000×3000 под ключ»  1 шт  185 920
```
Механизм: УНФ — «Наборы/Комплекты» + «Спецификации» + «Заказ-наряд»; УТ 11 — «Наборы» с печатью «как один товар»; ERP — «Ресурсные спецификации».

**20.** **Матрица цен на ворота — регистр сведений, а не номенклатура.** Заводить позицию на каждый типоразмер нельзя: ~740 бытовых + ~2200 промышленных ячеек × 3 серии = тысячи мёртвых позиций.
```
Номенклатура:    Ворота секционные Zaiger ECO     [Товар]
Характеристика:  3000×3000  (создаётся при первой продаже такого размера)

Регистр сведений «Цены поставщика по габаритам»
  Измерения: Производитель · Серия · Ширина · Высота · Дата
  Ресурс:    Цена закупки
  Загрузка:  обработкой из Excel-прайса поставщика, одной кнопкой
  Подбор:    округление габарита ВВЕРХ до следующего шага 100 мм
```

**21.** Опции ворот разделяются по механизму расчёта на три группы — в одном справочнике их держать нельзя:

| Группа | Примеры из прайса поставщика |
|---|---|
| **% от базы** | наклонный подъём +7% · высокий +12% · вал снизу +18% · GOLDEN OAK +10% · WENGE +10% · антикор +11% · пружины 50к +3% / 75к +5% / 100к +7% |
| **фикс. сумма** | встроенная калитка 57 091 · окно 7 372 · замок 7 798 · амортизатор 1 684 · защита от обрыва пружин 4 821 |
| **за м²** | фальшпанель S × 13 900 · покраска RAL S × 2 600 |

Полный алгоритм расчёта ворот:
```
1. Цена_закупки = Матрица(серия, Ш↑, В↑)
2. + Σ фиксированных опций
3. × (1 + Σ процентных наценок)
4. + фальшпанель (S × 13 900) + покраска (S × 2 600)
   = СЕБЕСТОИМОСТЬ
5. × (1 + интерес 11–12%)
6. + доставка (из прайса работ)
7. + монтаж (из прайса работ, с учётом м² и высотки)
8. × 1,12 если безнал
9. − скидка
   = ЦЕНА ДЛЯ КЛИЕНТА
```
**Это единственное место, где реально нужен программист 1С.** Всё остальное выше настраивается без кода.

### Юридическая часть

**22.** Схема «одна строка под ключ» законна и не является схемой: **договор подряда с выполнением работы иждивением подрядчика** (ст. 704 ГК) — материал принадлежит подрядчику, товарная накладная клиенту не нужна, достаточно акта. Условия:
   - договор оформлен подрядом, а **не** «купля-продажа + монтаж». Если товар выделен ценой в договоре — конструкция разваливается и накладную попросят законно;
   - списание через правильный счёт (п. 18);
   - **не все клиенты это примут.** Юрлицу, ставящему ворота на баланс как ОС, нужна стоимость ворот отдельно. Нужен **второй сценарий печати** — та же спецификация, развёрнутая печатная форма. При правильной структуре это переключение формы; при неправильной (товар как услуга) — тупик.

### Классификация типов цен
```python
import csv, re, collections
rows = list(csv.reader(open('ПРАЙС.csv', encoding='utf-8')))
cat = collections.Counter()
for r in rows:
    c = [x.strip() for x in r] + [''] * 6
    n, p = c[0], c[1]
    if not (n and p and n != 'Наименование работ' and len(n) < 200):
        continue
    pl = p.lower()
    if '%' in pl or 'коэф' in pl or pl.startswith('х2'):
        k = 'C. процент/коэффициент'
    elif re.search(r'(за|/)\s*(кв\.?м|м2|м\.?п\.?|час|н\.ч)', pl) or 'руб/м2' in pl:
        k = 'B. за м²/п.м./час'
    elif 'индивид' in pl or 'договор' in pl or 'уточ' in pl:
        k = 'D. не число'
    elif pl.startswith('от '):
        k = 'E. вилка «от»'
    elif re.match(r'^[\d\s]+$', pl.replace('\xa0', ' ')):
        k = 'A. фикс. сумма'
    else:
        k = 'D. не число'
    cat[k] += 1

tot = sum(cat.values())
for k, v in sorted(cat.items()):
    print(f'{v:4d}  {v*100//tot:3d}%  {k}')
```

### Проверка коэффициента безнала
```python
# ищет в расчётах пары (нал, безнал) и выводит фактический множитель
import csv, re
rows = list(csv.reader(open('РАСЧЕТЫ.csv', encoding='utf-8')))
num = lambda s: float(re.sub(r'[^\d,.]', '', s).replace(',', '.')) if re.search(r'\d', s) else None
for i, r in enumerate(rows, 1):
    vals = [num(x) for x in r if num(x)]
    for a, b in zip(vals, vals[1:]):
        if a and b and 1.05 < b / a < 1.20:
            print(f'стр.{i}: {a:.0f} -> {b:.0f}  (x{b/a:.3f})')
```
